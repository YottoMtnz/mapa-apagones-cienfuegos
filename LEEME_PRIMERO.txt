MAPA DE APAGONES DE CIENFUEGOS — AUDITORÍA Y MEJORA 3.0
Fecha: 7 de octubre de 2026

ALCANCE
Este proyecto sigue siendo SOLO de Cienfuegos y sus localidades dentro de la
provincia. El actualizador consulta únicamente empresaelectricacienfuegos1.
No se consulta Villa Clara ni se cambia de provincia al mover el mapa.
Se conservaron módulos/datos provinciales antiguos por compatibilidad, pero la
web publicada y su actualizador usan solamente Cienfuegos.

QUÉ TIENES QUE HACER — EN ORDEN

1. SEGURIDAD DEL BOT ANTERIOR
   Había una credencial de bot escrita en index.html. Se retiró del proyecto.
   En Telegram abre @BotFather, selecciona ese bot y revoca/regenera su token.
   El token viejo puede seguir en versiones anteriores del repositorio o en
   descargas antiguas. No basta con borrar la línea actual. No vuelvas a poner
   el token nuevo en HTML, JavaScript público ni archivos subidos al repositorio.
   Esta entrega NO necesita un token de bot para leer el canal.

2. INSTALAR LA ENTREGA
   Guarda una copia de tu proyecto actual. Extrae este ZIP y copia TODO el
   contenido de mapa-apagones al directorio raíz de tu repositorio existente.
   Incluye la carpeta .github, assets y scraper: no copies únicamente index.html.
   Conserva tus secretos de GitHub; no pegues credenciales dentro de los archivos.
   Sube los cambios a la rama main. No necesitas cambiar el nombre del repositorio.

3. COMPROBAR LOS SECRETOS DE GITHUB
   Settings > Secrets and variables > Actions:
     TG_API_ID
     TG_API_HASH
     TG_SESSION
   Si ya funcionaban, puedes conservarlos. Si la sesión caducó, ejecuta
   GENERAR_SESION.bat en tu PC con Python 3.12 instalado. Se abre el proceso de
   inicio de sesión de Telegram y obtienes TG_SESSION para guardarla como secreto.
   Nunca compartas la sesión: permite acceder a la cuenta de Telegram.

4. ACTIVAR LA PUBLICACIÓN CORRECTA
   Settings > Pages > Build and deployment > Source: GitHub Actions.
   El workflow publica directamente el sitio. El método anterior confiaba en
   un commit del bot para reconstruir Pages y podía quedarse sin publicar.
   Si tu repositorio protege main contra commits de Actions, ajusta esa regla
   para este flujo o el paso de guardar datos fallará de forma visible.

5. EJECUTAR LA PRIMERA LECTURA
   Actions > Mapa de Apagones Cienfuegos > Run workflow > modo actualizar.
   La primera ejecución instala Tesseract y el idioma español automáticamente.
   No necesitas contratar una API de IA ni configurar un proveedor de OCR.
   Revisa que finalicen los trabajos actualizar y publicar.
   Los datos incluidos no se presentan como una lectura nueva del canal:
   la primera ejecución con tus secretos es la que obtiene los avisos vigentes.

6. COMPROBAR EL RESULTADO
   Abre tu web y pulsa Actualizar. Si el navegador conserva archivos antiguos,
   recarga con Ctrl+F5. Comprueba el último aviso, los puntos y la sección de
   avisos por revisar. Cada circuito leído incluye acceso a su publicación.
   El cron solicita una ejecución cada cinco minutos; GitHub puede retrasarlo.
   La fecha del aviso y la última consulta se muestran por separado.

7. PREVISUALIZACIÓN LOCAL, OPCIONAL
   ABRIR_MAPA.bat abre la web en localhost y busca un puerto libre de 8780 a 8809.
   Necesita Python instalado. No inicia Telegram ni actualiza el canal.
   Mantén abierta su ventana; Ctrl+C cierra el servidor.
   Las teselas del mapa necesitan Internet. Leaflet y sus estilos ya van incluidos.

QUÉ SE CORRIGIÓ EN LA LECTURA DEL CANAL

- Reconstrucción cronológica: un restablecimiento nuevo ya no se deshace por leer
  después un aviso viejo de corte.
- Los mensajes editados se vuelven a leer; la edición invalida la caché de OCR.
  El orden sigue la fecha de publicación para no presentar una corrección de un
  aviso antiguo como si fuera un corte nuevo.
- IDs sin nombres de lugar y variantes C-31, C31, C 31, circuito 31, Cto. 31,
  listas numéricas y guiones tipográficos.
- Lectura por secciones: afectados, restablecidos y programados dentro de una
  misma publicación no se interpretan como un único estado para todos.
- Manejo de negaciones y frases como “se trabaja para restablecer”. Trabajar para
  reparar no confirma que el servicio haya vuelto.
- Déficit y averías separados. “Sin afectaciones por déficit” no borra una avería.
- Las listas completas sustituyen las anteriores en su ámbito. Dos publicaciones
  próximas en el tiempo no se mezclan automáticamente: esa suposición retenía
  cortes ya retirados. Los álbumes de Telegram sí comparten contexto.
- Cada aviso conserva fecha, identificador, enlace, procedencia y puntuación OCR.
- Nunca se supone que un corte se resolvió solo porque pasaron seis horas.
  La información vencida pasa a sin confirmar, no a verde.
- Un circuito ausente de una lista parcial tampoco aparece verde por defecto.
  Verde requiere un restablecimiento explícito reciente o un aviso provincial
  inequívoco de ausencia de afectaciones.
- Programaciones separadas del estado real. Se contemplan mañana, fechas simples,
  meses escritos y ventanas de hora sencillas, usando America/Havana.
  Una programación vencida desaparece, pero no se convierte automáticamente en
  apagón confirmado. Las fechas ambiguas quedan para revisión.
- Lectura de hasta 200 mensajes / tres días; límite de 16 documentos nuevos con
  OCR por ciclo para evitar ejecuciones interminables. La caché permite avanzar
  en ciclos posteriores; si se alcanza un límite se deja constancia.
- Los errores de conexión conservan el estado anterior, muestran advertencia y
  hacen fallar la ejecución de forma visible; no vacían la lista para mostrar luz.
- Escritura atómica del JSON y exclusión mutua del workflow para evitar carreras.
- FloodWait de Telegram se respeta; esperas largas se dejan para otro ciclo.

FOTOS, ÁLBUMES Y PDF

Ahora se descargan temporalmente las imágenes y se reconoce texto con Tesseract.
Se corrigen orientación y contraste; se prueban disposiciones de texto distintas.
Se combinan el pie de foto y el contenido; los álbumes comparten el encabezado.
Los PDF con texto se extraen directamente y los escaneados pasan por OCR.

Si no se puede leer una imagen, tiene baja calidad, un código OCR no está en el
catálogo o la interpretación es ambigua, se registra en “avisos por revisar”.
No se inventa una conclusión. Los medios incompletos tampoco tienen permiso para
vaciar una lista vigente. Vídeos y audios quedan pendientes: no se transcriben.

Límites: documento de 12 MB, PDF de hasta cinco páginas, confianza OCR mínima 65.
La puntuación es una señal del motor OCR, no una garantía estadística de exactitud.
Un gráfico basado únicamente en colores, una tabla compleja o una foto ilegible
pueden necesitar revisión. Esto es OCR y reglas mejoradas; NO es comprensión
infalible de cualquier cambio de redacción o imagen.

QUÉ SE CORRIGIÓ EN LAS UBICACIONES

Antes: 52/60 circuitos con alguna ubicación y 119 puntos.
Ahora: 58/60 circuitos con alguna ubicación y 140 puntos.
Quedan sin pin C-3 y C-65; además hay localidades pendientes dentro de circuitos
parcialmente ubicados. El número de puntos NO significa viviendas ni personas.

- Se incorporó el límite geográfico real de Cienfuegos de OpenStreetMap.
- Se retiraron tres puntos fuera de la provincia: La Jutía, Viet Nam y Santa Susana,
  tal como estaban ubicados en la entrega original. No se afirma que no existan
  lugares homónimos en Cienfuegos: se descartaron esas coordenadas concretas.
- Se retiraron otras referencias incompatibles sin respaldo; Parque José Martí
  se separó de su homónimo de Cruces y conserva marca de revisión donde corresponde.
- Se verificaron ubicaciones con Nominatim y con localidades de OpenStreetMap
  contenidas en la provincia. Se añadieron referencias a Abreus, Palmira,
  Pasacaballos, San Fernando de Camarones, La Pollera y otras localidades.
- Se incluyeron alias ortográficos explícitos, por ejemplo Caonao/Caunao.
- Se corrigió la lectura de address.province además de address.state.
- Ya no se decide la provincia por la capital más cercana ni por una caja que
  se solapa con provincias vecinas. Se comprueba el límite real.
- No se elige arbitrariamente el primer homónimo ni un negocio con nombre parecido.
- Se eliminó el fallback de coincidir con cualquier fragmento de un nombre.
- Las referencias al centro de un pueblo se etiquetan como ubicación a nivel
  de localidad; no se presentan como la calle exacta del circuito.
- Las ubicaciones heredadas no verificadas siguen marcadas para confirmar.
- Los botones Mover punto / Enviar corrección vuelven a estar disponibles.
  Mover guarda solo en tu dispositivo; Enviar abre un issue de GitHub para revisión.
  No modifica la ubicación para todos automáticamente.

Detalle verificable: data/cambios_ubicaciones.json, data/verificacion_osm.json,
data/auditoria_geografica.json y data/gazetteer.json.
Fuentes: OpenStreetMap / Nominatim / Overpass. Licencia ODbL 1.0 y atribución a
sus colaboradores. Cada nueva referencia OSM del catálogo incluye su enlace.

ESTÉTICA Y USO

- Panel renovado, mejor jerarquía, tarjetas claras y colores coherentes.
- Buscador por localidad o circuito, independiente de los filtros de estado.
- Contadores de circuitos, sin sumar varias veces los pueblos de un mismo circuito.

REPORTES COMUNITARIOS Y ADMINISTRACIÓN — OPCIONALES

El envío directo desde la página a Telegram se retiró porque exponía el token.
El mapa y la lectura del canal funcionan sin configurar estos módulos.

Si quieres reportes comunitarios, configura el Worker siguiendo worker/DESPLEGAR.md
y su URL reportApi en config.js. Los botones quedan ocultos hasta configurarlo.
Ahora hay elecciones Sí / No / Cancelar: cancelar no envía un reporte de apagón.
Se verifica la respuesta del servidor antes de mostrar que el envío tuvo éxito.
Los reportes de usuarios no sustituyen automáticamente la información del canal.

El panel admin anterior verificaba la contraseña solo en el navegador y el
servidor aceptaba aprobar/rechazar sin autenticación. Ahora el servidor verifica
ADMIN_TOKEN, las acciones de escritura requieren POST y se validan las filas.
Se filtran HTML y fórmulas de hoja de cálculo.
Para usarlo: desplegar admin/Code.gs, configurar SHEET_ID y un ADMIN_TOKEN aleatorio
largo (mínimo 24 caracteres) en Propiedades del script, y adminUrl en config.js.
La hoja correcciones lleva columnas Fecha, Provincia, Circuito, Lugar, Lat, Lng,
Estado. Aprobar registra la decisión; no publica cambios de coordenadas por sí solo.
La página principal utiliza issues de GitHub para las correcciones de ubicación.
